Ce que le site garde et ce qu'il appelle

  • Le site ne dépose aucun cookie et ne mesure pas l'audience.
  • Il garde dans votre navigateur deux informations : la dernière espèce consultée (clé champi-espece) et le dernier département affiché (champi-departement), pour les rouvrir à la visite suivante. Elles ne quittent jamais votre appareil.
  • Vos coins (« Mes coins ») sont gardés au même endroit (clés champi-coins et champi-coins-effaces, la liste des trouvailles effacées) : le site n'a pas de serveur qui pourrait les recevoir. Ils disparaissent si vous effacez les données du site, et Safari les efface de lui-même après sept jours sans visite (sauf si le site est ajouté à l'écran d'accueil) : sauvegardez-les dans un fichier, ou synchronisez-les (ci-dessous). Partager vos coins crée un fichier que vous envoyez vous-même ; ceux qu'on vous a confiés n'y figurent pas.
  • Pour s'ouvrir sans réseau en forêt, le site garde dans le navigateur une copie de ses propres fichiers et des données déjà consultées (caches champi-hors-ligne-…) : rien d'autre, ni les fonds de carte, ni vos coins, qui ont leur propre place. Effacer les données du site la vide.
  • Si vous activez la synchronisation, le jeton GitHub est gardé dans le navigateur (clé champi-synchro), ainsi que le prénom qui signe vos coins (champi-nom) ; vos coins sont envoyés à api.github.com, dans le dépôt privé du lien, et nulle part ailleurs.
  • À l'ouverture, la carte demande la position de l'appareil pour se placer sur votre département et afficher où vous êtes ; si vous refusez, elle ne redemande plus (le navigateur garde votre choix). Elle sert aussi à « Ma position » et à « Noter une trouvaille à ma position ». Elle n'est envoyée nulle part.
  • Les fonds de carte sont chargés directement depuis les serveurs de l'IGN (data.geopf.fr), qui reçoivent donc votre adresse IP, comme pour toute carte en ligne. La bibliothèque de carte (Leaflet) est servie par le site lui-même.

Retrouver ses coins sur tous ses appareils

Les coins peuvent se synchroniser entre votre téléphone, votre ordinateur et tout autre appareil, par un dépôt GitHub privé qui vous appartient. Le site n'a toujours pas de serveur : chaque navigateur lit et écrit lui-même un fichier dans ce dépôt.

  1. Sur GitHub, créez un dépôt privé (par exemple champi-coins), en cochant « Add a README file ».
  2. Créez un jeton à accès limité : Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token. Dans « Repository access », choisissez « Only select repositories » et ce seul dépôt ; dans « Permissions », donnez à « Contents » l'accès « Read and write ». Rien d'autre.
  3. Composez le lien : l'adresse de la carte suivie de #depot=votre-compte/champi-coins&jeton= et du jeton. Ouvrez-le une fois sur chaque appareil : le jeton est gardé dans le navigateur et retiré de la barre d'adresse. La carte demande votre prénom, qui signe vos coins. Le panneau « Mes coins » dit ensuite quand a eu lieu la dernière synchronisation.
  • Le lien vaut une clé : qui l'a peut lire et modifier les coins du dépôt, et rien d'autre (le jeton n'ouvre que ce dépôt). Gardez-le dans vos notes ou votre gestionnaire de mots de passe ; il peut aussi rester dans l'historique du navigateur.
  • La carte garde sa copie : elle marche sans réseau, et ce qui a été noté en forêt part au prochain passage en ligne. Un coin effacé sur un appareil l'est partout. Chaque envoi est une version du dépôt : une erreur se rattrape dans son historique.
  • Un jeton finit par expirer : la carte le dit, garde tout, et il suffit d'un nouveau jeton et d'un nouveau lien. Si Safari a effacé les données du site, rouvrez le lien.

Partager ses coins avec un groupe

Le même lien, donné à des proches, en fait un groupe : chacun voit les coins du dépôt sur sa carte et peut en noter, d'un appui long. C'est un lien que vous distribuez, jamais l'adresse du site : les coins ne sont lisibles que par ceux qui l'ont.

  • En ouvrant le lien, chacun donne son prénom ; ses coins en portent la signature (« coin de Paul ») et apparaissent en pointillés chez les autres. Chacun n'efface que les siens.
  • En rejoignant le groupe, la carte demande si les coins déjà notés sur l'appareil y partent ; sinon, ils restent sur l'appareil. Au moment de noter une trouvaille, la case « Seulement sur cet appareil » la garde pour soi. Les coins confiés par fichier ne partent jamais dans le groupe.
  • Pour qu'une personne voie les coins sans pouvoir en ajouter, créez un second jeton sur le même dépôt avec « Contents » en « Read-only », et donnez-lui le lien fait avec ce jeton : ses propres coins restent alors sur son appareil.
  • Tout se fait sous votre compte GitHub : les envois des membres apparaissent à votre nom dans l'historique du dépôt. Un lien transmis par un membre fait un membre de plus ; pour reprendre la main, supprimez le jeton et donnez un nouveau lien à ceux que vous gardez.

Être prévenu sur son téléphone

Chaque matin, après le calcul de la carte, une notification part pour chaque département suivi quand une espèce y passe à « bonnes conditions » dans les quatre jours qui viennent : « Vendée : c'est le moment pour le bolet bai ». Une espèce déjà bonne la veille ne sonne pas une seconde fois. L'envoi passe par ntfy, un service de notifications gratuit et sans compte ; votre navigateur n'y est pour rien.

  1. Installez l'application ntfy (Android ou iPhone) et abonnez-vous à un canal au nom long et imprévisible, par exemple champi- suivi d'une suite de lettres au hasard : qui connaît ce nom reçoit les alertes.
  2. Dans le dépôt GitHub du site, Settings → Secrets and variables → Actions : un secret NTFY_TOPIC avec ce nom, et une variable ALERTES avec les numéros des départements suivis, séparés par des virgules (par exemple 85,74).

Pour partager les alertes avec votre groupe, donnez-lui le nom du canal. Sans canal, rien n'est envoyé.

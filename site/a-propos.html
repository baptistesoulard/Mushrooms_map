Ce que le site garde et ce qu'il appelle

  • Le site ne dépose aucun cookie et ne mesure pas l'audience.
  • Il garde dans votre navigateur deux informations : la dernière espèce consultée (clé champi-espece) et le dernier département affiché (champi-departement), pour les rouvrir à la visite suivante. Elles ne quittent jamais votre appareil.
  • Vos coins (« Mes coins ») sont gardés au même endroit (clés champi-coins et champi-coins-effaces, la liste des trouvailles effacées) : le site n'a pas de serveur qui pourrait les recevoir. Ils disparaissent si vous effacez les données du site, et Safari les efface de lui-même après sept jours sans visite (sauf si le site est ajouté à l'écran d'accueil) : sauvegardez-les dans un fichier, ou synchronisez-les (ci-dessous). Partager vos coins crée un fichier que vous envoyez vous-même ; ceux qu'on vous a confiés n'y figurent pas.
  • Si vous activez la synchronisation, le jeton GitHub est gardé dans le navigateur (clé champi-synchro) et vos coins sont envoyés à api.github.com, dans votre propre dépôt privé, et nulle part ailleurs.
  • La position de l'appareil n'est demandée que lorsque vous appuyez sur « Ma position » (sur la carte) ou sur « Noter une trouvaille à ma position ». Une fois que vous l'avez autorisée, la carte s'en sert aussi à l'ouverture pour choisir votre département, sans redemander. Elle sert à afficher le point, choisir le département et placer un coin ; elle n'est envoyée nulle part.
  • Les fonds de carte sont chargés directement depuis les serveurs de l'IGN (data.geopf.fr), qui reçoivent donc votre adresse IP, comme pour toute carte en ligne. La bibliothèque de carte (Leaflet) est servie par le site lui-même.

Retrouver ses coins sur tous ses appareils

Les coins peuvent se synchroniser entre votre téléphone, votre ordinateur et tout autre appareil, par un dépôt GitHub privé qui vous appartient. Le site n'a toujours pas de serveur : chaque navigateur lit et écrit lui-même un fichier dans ce dépôt.

  1. Sur GitHub, créez un dépôt privé (par exemple champi-coins), en cochant « Add a README file ».
  2. Créez un jeton à accès limité : Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token. Dans « Repository access », choisissez « Only select repositories » et ce seul dépôt ; dans « Permissions », donnez à « Contents » l'accès « Read and write ». Rien d'autre.
  3. Composez le lien : l'adresse de la carte suivie de #depot=votre-compte/champi-coins&jeton= et du jeton. Ouvrez-le une fois sur chaque appareil : le jeton est gardé dans le navigateur et retiré de la barre d'adresse. Le panneau « Mes coins » dit ensuite quand a eu lieu la dernière synchronisation.
  • Le lien vaut une clé : qui l'a peut lire et modifier vos coins, et rien d'autre (le jeton n'ouvre que ce dépôt). Gardez-le dans vos notes ou votre gestionnaire de mots de passe ; il peut aussi rester dans l'historique du navigateur. Pour confier des coins à quelqu'un, le partage par fichier reste le bon outil.
  • La carte garde sa copie : elle marche sans réseau, et ce qui a été noté en forêt part au prochain passage en ligne. Un coin effacé sur un appareil l'est partout. Chaque envoi est une version du dépôt : une erreur se rattrape dans son historique.
  • Un jeton finit par expirer : la carte le dit, garde tout, et il suffit d'un nouveau jeton et d'un nouveau lien. Si Safari a effacé les données du site, rouvrez le lien.
